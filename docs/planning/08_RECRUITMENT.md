# 팀원 모집 및 킥오프 (v0.2)

## 공유할 모집 공고 초안
**[팀원 모집] 기존 Vue + Flask QR 주문 시스템을 실제 매장 운영 서비스로 고도화할 개발팀**

목포대학교 학생 포차 주문 시스템을 출발점으로, 이미 구현된 **Vue 3 화면과 Flask/SQLAlchemy 주문·캐셔·주방·서빙 서버**를 진단·개선해 매장에서 사용할 수 있는 서비스를 만들고자 합니다. 기존 코드의 주문/취소·재고 정합성, 인증, 매장 설정, 테스트, 배포를 먼저 해결하며, 이후 Mock 결제·정산·ERP CSV/연동까지 심화합니다.

단순한 기술 스터디나 화면 기능 추가가 목표가 아닙니다. 실제 이슈를 재현하고, 팀이 설계·PR 리뷰·테스트·모니터링·운영하는 과정까지 경험합니다. 최초 목표는 한 매장의 QR 주문·주방·서빙·매출 확인 파일럿입니다. *아직 파일럿 매장은 확정하지 않았습니다.* 실제 PG 연동/상용화는 별도 검토 뒤 결정합니다.

- **보유 소스**: https://github.com/Capybara-Clinic/mnu_pub_order_system / https://github.com/Capybara-Clinic/capybara-qr-order
- **초기 기술**: Vue 3, Flask, SQLAlchemy, MySQL 계열 DB, Docker, GitHub Actions(도입 예정).
- **모집 역할**: 백엔드 1~2, 프론트엔드 1~2, QA/Infra 겸임 1, PM/기술리더 겸임 가능. 목표 4~6명.
- **활동 방식**: 제안 16주, 주당 개인 6~10시간 가정, 2주 Sprint, 주 1회 공유/데모, PR·테스트 필수.
- **참여 기준**: 높은 숙련도보다 끝까지 문제를 해결하고 작은 PR을 완수하는 책임감, 검증·리뷰·기록 가능성.
- **지원 시**: GitHub/개인 작업 1개, 희망 역할, 현실 투입 시간, 해결하고 싶은 이슈 1개(정합성/결제/관리/운영 중).

## 선발/매칭용 과제 예시(강제 사전 무료노동 금지)
- BE: `cancel_order` 재고 정책 이슈를 읽고 예상 버그·테스트 케이스 2개 제안.
- FE: `CashierDashboard`의 Pinia mock↔서버 DB 불일치 원인을 설명하고 API 연동 방안 제안.
- QA/Infra: 재고 1개 동시 주문 시나리오를 테스트 계획으로 작성.
