# 변경 이력 / 결정 기록 — v0.1 → v0.2

## 변경 개요
| 문서/항목 | v0.1 | v0.2 |
|---|---|---|
| 분석 범위 | FE 저장소만 | **FE+실제 Flask BE 코드** |
| 권장 백엔드 | Spring Boot 중심, Flask 대안 | **Flask 유지 기본**, Spring 별도 대안 |
| 데이터베이스 | PostgreSQL 중심 | **현재 MySQL 계열 모델 유지**, 점진 이관 |
| 스키마 관리 | Flyway 후보 | **Alembic/Flask-Migrate** 후보 |
| 현재 기능 | 주문·재고 백엔드 존재 여부 미확인 | 7개 ORM 모델·5개 Blueprint 확인 |
| 초기 스프린트 | 신규 서버 구축 중심 | **재고·취소·인증·결제 상태 결함 재현·수정** |
| DB 설계 | 신규 To-Be 위주 | **현행 모델과 migration 경로** 포함 |
| API | 신규 REST v1 중심 | **현행 API 매트릭스**→안전한 v1 이행 |
| 팀 모집 | BE 불명확 | 기존 Flask BE 기능·실제 이슈 제시 |
| 문서 구성 | 14개 파일 | 신규 API/불변식/DB 이관/보안 운영/통합 요약 추가 |

## 2026-10-14 기준 미결정 (팀 ADR로 확정)
- DEC-001 Flask 유지 vs Spring 재구현: **제안 Flask 유지**, 최종 팀 승인 대기.
- DEC-002 실제 DB 엔진/버전(MySQL vs MariaDB), 운영 스키마 존재/데이터 마이그레이션.
- DEC-003 주문 재고: 즉시차감 vs 결제 중 예약, 만료·취소 복원 정책.
- DEC-004 계좌이체 수동확인 업무를 유지할지, PG sandbox를 언제 붙일지.
- DEC-005 기존 FE/BE 코드 재배포권·기여자 동의, 백엔드 LICENSE 결정.
- DEC-006 팀 문서의 정본 저장소, 장기 monorepo 여부.
- DEC-007 테이블/손님 회차의 QR 권한 토큰·이력 정책.
- DEC-008 파일럿 점주 확보, 고객 개인정보의 수집 필요성 및 보유·삭제 정책.
- DEC-009 멀티매장 도입 시기 및 다중 테넌트 모델.

## 검증되지 않은 주장(유의)
- 실제 서비스가 가동 중이라거나 운영 지표가 존재한다고 단정하지 않는다.
- 버그는 **소스상의 불일치가 확인된 것**과 **실행 재현이 필요한 것**을 구분한다.
- PG 라이브 사용, 세무/정산 구조의 합법성은 별도 확인 필요.
- 본 계획은 팀 협업 초안이며 소스 저장소 자체 수정/배포는 수행하지 않았다.
