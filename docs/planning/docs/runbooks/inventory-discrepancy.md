# Runbook: 주문·재고 수량 불일치 대응 (파일럿)

- Owner: 주문/재고 도메인 담당 + 운영 담당
- 적용 전제: 서버 API에 재고 이동/취소 로그와 관리자 접근 제어가 구현된 뒤 사용

## 감지
판매가능 수량 < 0, 주문 취소 시 예상치보다 재고 증가, 물리재고와 시스템 재고 차이, 주문 중복 의심.

## 초기 대응
1. 해당 메뉴의 온라인 신규 주문을 안전한 관리자 기능으로 중단(임의 DB 변경 금지).
2. 주문 ID, 매장 ID, 메뉴 ID, 요청 ID, 재고 이동 이력, 주문/취소 시각과 상태 확보(개인정보 제외).
3. 주문 차감/복원 쌍과 `source_event_id` 중복, 성공 주문과 실패 요청 DB 부작용 조사.
4. 물리 재고 확인 후 책임자 승인 하에 보정 거래(`MANUAL_ADJUST`)를 남긴다. 원 거래 삭제 금지.
5. 필요 시 주문 고객 안내/현장 대체, 대사 재실행과 누락·중복 주문 검증.
6. 원인·영향 건수·차액·복구시각·회귀테스트/배포 버전을 기록한다.

## 주의
현재 저장소에는 `inventory_movements`가 없으므로 이 Runbook의 전체 작업은 **To-Be**이며 실제 구현 이후 활성화한다.
