# 완료 정의 (Definition of Done)

## 1. 목적 및 적용 범위

AI의 작업 완료를 단순히 코드 생성 여부가 아닌 **요구사항 충족·검증·변경 통제·보고**로 판정한다. 모든 항목이 해당되는 것은 아니며 미적용 항목은 N/A와 이유를 적는다.

## 2. 작업 체크리스트

### 요구사항

- [ ] 요청 목적 및 범위에 해당하는 기능/수정 사항을 반영했다.
- [ ] 요청과 무관한 변경이 없거나, 해당 변경의 이유와 승인을 기록했다.
- [ ] 정상·오류·경계 조건을 고려했다.

### 구현 품질

- [ ] 기존 아키텍처·명명·포매팅 규칙과 충돌하지 않는다.
- [ ] 예외/입력/권한/데이터 무결성을 점검했다.
- [ ] 비밀 정보·개인정보·원치 않는 산출물이 diff에 없다.
- [ ] 새 의존성·인터페이스·설정 변경이 있다면 영향을 설명했다.

### 검증

- [ ] 관련 테스트를 추가·수정했다(해당 시).
- [ ] 관련 테스트의 PASS/FAIL/NOT RUN을 명확히 기록했다.
- [ ] 사용 가능한 린터·타입 검사·빌드 결과를 기록했다.
- [ ] 성능·보안·DB 변경은 관련 위험과 필요한 추가 검증을 적었다.

### 문서 및 전달

- [ ] 필요 시 사용자 문서/API 계약/`PROJECT_CONTEXT.md`를 갱신했다.
- [ ] 변경 파일·주요 변경 사항·검증 결과를 요약했다.
- [ ] 알려진 제한, 미확인 사항, 후속 작업을 명시했다.
- [ ] 커밋·푸시·배포는 **요청 및 권한이 있는 경우에만** 수행했다.

## 3. 상태 판정

| 결과 | 판정 기준 |
| --- | --- |
| DONE | 요구사항 충족, 필요한 검증 통과, 중요 위험/미결 사항 없음 |
| DONE WITH LIMITATIONS | 주요 요구사항 구현, 단 미검증/제약이 존재하고 명확하게 공개됨. 최종 승인 여부는 사용자 판단 |
| BLOCKED | 요구사항 달성을 막는 조건 존재(접근 권한, 실패한 테스트, 불명확한 계약 등) |
| IN PROGRESS | 핵심 작업이 미완료이거나 구현 중 |

`NOT RUN`을 `PASS`로 대체하지 않는다. 검증 불가 항목이 핵심 요구사항에 해당하면 완료로 판정하지 않는다.

## 4. 작업 결과 보고 템플릿

```text
상태: DONE | DONE WITH LIMITATIONS | BLOCKED | IN PROGRESS
변경: <무엇을, 왜>
파일: <실제 변경 파일 경로>
검증: <명령> — PASS/FAIL/NOT RUN + 이유
위험: <호환성/보안/성능/마이그레이션 영향>
후속: <필요한 작업 또는 없음>
Git: <사용자 요청으로 실행한 작업만>
```
